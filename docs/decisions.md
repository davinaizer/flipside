# Implementation decisions

Product decisions live in docs/PRD.md section 18. This file holds what happens while building.

- `ASSUMED: <what, why>` is logged by a worker that took a PRD-stated default. The user reviews these in the PR.
- `ANSWER (<task id>): <question> -> <answer>` records what the user decided when a worker was blocked.

ANSWER (F0.3): Which container runtime? -> Podman instead of Docker (PRD D20). `podman compose` needs a separately installed provider, so scripts call `podman run` directly.
ANSWER (F3.8): Where is the school deck? -> Supplied in `res/`; its zip keeps images under `images/` while the CSV names bare files, so image names match by base file name.
ASSUMED: settings ids (atkinson, lexend, system; textSize 1-4, spacing 1-3, default card colour mist) and newCardsPerDay max 100, since the PRD names options without ids.
ASSUMED: container user/db/password flipside/flipside/flipside (local-only, 127.0.0.1 bound), container removed on db:down while the named volume stays.
ASSUMED: integration tests read the server version via podman exec psql, since the Postgres driver arrives in F0.5 and none is allowed yet; container name is flipside-test-<pid>-<random>, port from a free-port probe.
ASSUMED: Postgres driver is `postgres` (postgres-js) with drizzle-orm/drizzle-kit; enums are checked text columns; box range 1-5 checked on card_state and review_log; migration journal lives in public.schema_migrations; sessions and review_log ids are client-supplied (no default).
ASSUMED: pnpm db:migrate uses drizzle-kit migrate (no new dependency); start-up migration runs from src/instrumentation.ts via the same drizzle migrator.
ASSUMED: seed matches profiles by name and only inserts missing ones; placeholder avatars fox/owl, accent stored as "primary" (design primary token), seed script runs under plain Node 26 type stripping with a resolve hook for the "@/" alias since tsx is not a dependency.
ASSUMED: box tokens are derived from design palette (Not yet peach #ffdcc4 on #6f3800, Nearly buttercream #fef9c3 on darkened #5c4700, dark Nearly #463c00 on #fff1a8, dark Not yet #4f2500 on #ffdcc5) to reach 4.5:1 (README item 9); tokens use short semantic names (surface, on-surface, box-got-it) via Tailwind v4 @theme in CSS, no tailwind config file; on-primary-container light set to #ffffff for contrast.
ASSUMED: font id stays `system` (shipped in F0.2) instead of `system-sans`; src/ui/font-ids.ts maps it to the system stack. Fonts are the OFL variable TTFs from the googlefonts GitHub repos, committed in src/ui/fonts/.
ASSUMED: e2e uses @playwright/test and @axe-core/playwright (PRD section 9 test stack); webServer runs scripts/e2e-server.mjs (throwaway Podman Postgres, next build + start on port 3100, E2E_PORT overrides) with a detached watchdog removing the container if Playwright kills it; both projects use Chromium, iPad is 1180x820 with touch; run `pnpm exec playwright install chromium` once.
ASSUMED: dayStartUtc resolves a day start hour skipped by a clock change to the moment the clocks jump, and a repeated hour to its first occurrence; the PRD only fixes 07:00 London where neither happens.
ASSUMED: applyGrade keeps a suspended or leech status when graded (only active becomes leech at the threshold), and reps counts every grade including re-queued attempts; the PRD does not say how grading changes these.
ASSUMED: session builder weak scope keeps the due-date rule (section 5 applies candidates after scope), so a not-due leech waits for its due date; topic scope is (deckId, topic) pairs since topics live per deck; new cards keep caller order (deck position) rather than being shuffled; explicit card lists (misses) ignore due dates and use the same order rule; candidateCount is returned so labels can show the session-sized count.
ASSUMED: session queue reads "after about four other cards" as exactly REQUEUE_GAP (4) other entries, appending when four or fewer remain; each attempt is its own queue entry (progress bar total grows on re-queue); a third Not yet on a card is graded but not re-queued; undo at the session start is a no-op and grading a finished queue throws; the PRD fixes none of these details.
ASSUMED: CSV row numbers count the header as row 1 (first card is row 2); a missing id column gives one file-level warning and an empty id cell a row warning; derived id is "auto-" plus a 64-bit FNV-1a hash of normalised topic and front (no Node crypto, browser-safe); header names are matched case-insensitively; short rows are padded as empty cells, and an unclosed quote blocks the import.
ASSUMED: zip image names match case-insensitively by base file name (both / and \ separators); SVG is detected by text sniff since file-type does not report it; symlinks are read from the central directory (Unix made-by plus mode 0120000); entry count and size limits use the directory before inflating, and inflated size is re-checked; directories are skipped, and a Windows drive path counts as absolute.
ASSUMED: stats count first attempts by the stored is_first_attempt_today flag (same filter as the section 10 query) rather than re-deriving them; days practised counts any non-undone review; the month range is the four Monday-aligned weeks ending with the current week, previous period is the equal span before it; median of an even count is the mean of the middle two.
ASSUMED: change wording is "N more/fewer (days) than last week", "N points higher/lower" (rounded percent), "N s faster/slower" (rounded seconds), "Same as last week", "the previous four weeks" for month, and null when either side has no data; Focus next groups by (deckId, topic), sums lapses for ties, then topic name; by-deck puts decks without cards last; mastery buckets ignore status.
ASSUMED: X-Profile-Id header wins over the cookie when both are present (explicit non-browser client); services throw ApiError and routes map it with toErrorResponse.
ASSUMED: POST /session/profile takes {profileId}, returns 400 for a malformed body and 404 for an unknown id (the PRD says "rejects"); cookie Max-Age is one year, Path=/; /me adds accent, timezone and dayStartHour to the profile and fills stored settings with schema defaults.
ASSUMED: F2.3 library returns a flat decks list with cardCount only (groupName per deck, ordered by group then name); GET /decks/{id} returns {deck} with topics and counts; malformed deck ids are 404.
ASSUMED: picker is a client component fetching GET /profiles (gives loading and error states); "/" validates the cookie server-side via resolveHome; placeholder avatars are emoji glyphs behind src/ui/avatars; e2e server now runs db:seed before start so Davi and Nicole exist.
ASSUMED: app shell pages are server components calling services directly via profileFromCookie (layout redirects to / when null); deck not-found uses (app)/not-found.tsx; Library stays highlighted on /decks and /import; e2e cannot seed decks (no create API yet) so deck listing by name rests on getLibrary tests plus the empty state.
ASSUMED: e2e decks come from scripts/e2e-seed.ts (one deck per profile, run by the e2e server after db:seed) because no deck create API exists yet; the production seed is unchanged.
ASSUMED: ImageStore.get returns a web ReadableStream and throws ImageNotFoundError; bad keys throw InvalidImageKeyError; disk put skips writing when the key exists (content-addressed); mime is accepted but unused by the disk driver.
ASSUMED: image Content-Type uses the mime stored at import (sniffed from bytes then); ETag is the quoted hash and If-None-Match accepts quoted, weak or bare hash; a row whose file is missing from the store answers 404.
ASSUMED: dry run answers 422 import_blocked (issues in details) for blocked files and 200 with errors/warnings otherwise; the upload field is "file", zip vs CSV is told by the PK magic bytes, a zip needs exactly one .csv entry (any folder), and POST /imports without dryRun answers 501 until F3.4.
ASSUMED: POST /imports takes multipart fields file, name, group (optional), color (one of the card colours), answerStyle; answers 201 with {deckId, added, updated, skipped, imageCount, warnings}; a file with no valid cards is blocked (422); an empty upload now reaches the parser (422 empty_file) instead of 400. Image files are written inside the transaction, so a failed write rolls back rows and orphan files wait for cleanup.
ASSUMED: re-import is POST /imports with a deckId field (deck details then ignored, deck settings unchanged); matched cards keep their position and new cards go after the last one; an image cell naming a picture the upload cannot supply (CSV only, missing or rejected) keeps the current image while an empty cell clears it; missing ids are returned as `missing` and stored as `card_not_in_file` warnings in import_runs; the result adds `unchanged` (0 for a new deck); a soft-deleted card with a matching id is updated but not restored.
ASSUMED: export zip holds deck.csv and images/<sha256>.<ext> (hash names dedupe repeats); template is GET /api/v1/imports/template with no profile needed; export file name is the deck name made filename-safe.
ASSUMED: import CLI defaults deck name to the file name, colour mist and answer style bullets when flags are omitted; --deck re-imports; it matches the profile by exact name and prints the ImportResult as JSON.
ASSUMED: import screen parses in the browser via domain/import-file.ts (parseImport and preview moved out of the server service, which now wraps it); existing decks come from getLibrary on the server page, and the existing-deck choice is a select in the form; success actions are Open deck and Back to library; component tests use static markup (no jsdom dependency).
ASSUMED: F3.13 simplifications: re-import stays the "Add to" select inside Deck details (no checkbox in step 1), the button reads "Add N cards" for a new deck and "Update deck" for a re-import; omitted Import Readiness tile, Inspect row link, per-topic colour chips, selected-tint caption and the found/not-found column chips (the existing "Columns found" line stays); card colours got new --card-* tokens in tokens.css (no card palette existed; values chosen to fit the surface scale); the e2e 44 px helper also skips sr-only radios inside a label, as it did for the file input.
